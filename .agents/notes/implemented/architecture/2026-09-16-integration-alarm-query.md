# Agent Note: Alarm query capability seam — one REST backend behind a closed vocabulary

Status: implemented

English | [中文](2026-09-16-integration-alarm-query.zh.md)

## Problem

The agent had no way to read alarms from a real alarm system: no service owned alarm vocabulary or provider selection, and a transport card for alarm results would have required provider code inside the Feishu package. Alarm platforms also return vendor-shaped payloads that vary per system, so a tool reading raw JSON would make the model parse prose-like structures and let mislabeled severities pass silently.

## Decision

- **One capability seam in a new `packages/integration/` group, three roles in three packages.** `dsh-integration-alarm` owns `ctx.alarmQuery`: the provider registry, the explicit `resolve(request): AlarmQuerySpec` defaulting step (seam default `maxAlarms` 20), the registration-order-independent selection ladder, and `AlarmError extends HarnessError` with a closed code union. `dsh-integration-alarm-http` maps one documented REST contract into the seam. `dsh-tool-integration-alarm` owns the model-facing schema, render, and presentation. Future systems repeat the split instead of growing any package sideways.
- **The seam owns a closed alarm vocabulary.** Severity (`critical|high|medium|low`), status (`firing|acknowledged|resolved`), and the field set are seam types; timestamp fields are ISO-8601 by contract, checked with the seam-exported `isIso8601Timestamp` so wire decoding and model-input validation share one rule. The HTTP provider decodes vendor JSON strictly at the wire boundary — unknown keys, wrong types, out-of-vocabulary values, non-ISO timestamps, or an `alarms` list longer than `total` fail loud as `ALARM_PROVIDER_FAILED`. That strictness belongs to the standard gateway protocol this package defines; a provider adapting a drift-tolerant system chooses its own policy as its own package. Downstream code trusts TypeScript.
- **Retry only what idempotence covers.** Network failures, timeouts, token-resolution errors, and HTTP 429/5xx retry with doubling backoff within Config bounds; decode failures, bodies over the byte budget, and every other status fail on the spot, and caller cancellation is never retried. Timeout is per attempt, combined with the caller signal through `AbortSignal.any`, and bounds credential resolution too: the token promise races the attempt's abort guard, and a losing resolution keeps running unobserved with its result discarded.
- **Auth is an explicit mode, never a fallback.** `auth: bearer` (default) resolves the token per attempt and fails loud as `ALARM_PROVIDER_FAILED` before any request when nothing resolves — an anonymous request is never sent by accident; `auth: anonymous` reads no token and sends no header.
- **The base URL is resolved once, into a directory.** `resolveAlarmBase` admits absolute `http`/`https` URLs without query or fragment and slash-terminates the pathname at plugin load, so `…/api/v1` and `…/api/v1/` both query `…/api/v1/alarms` and no path segment is dropped; the provider receives the resolved URL, never a raw string.
- **Responses and details are bounded before they are rendered.** The provider streams the body under `maxResponseBytes` and cancels the stream as the budget crosses, so an oversized answer is never downloaded whole; the tool caps each alarm's `detail` at `maxDetailChars` inside the canonical value, cutting, ellipsizing, and flagging it `detailTruncated`, so the value, the session log, the card, and the meta builder never see a giant field at full size.
- **The model never sizes its own results.** `alarm_query` exposes filters only; the deployment bound (`maxAlarms`, 1–100, default 20) is a Config field applied through the seam's resolution step.
- **Presentation meta over the ceiling degrades, not truncates.** The tool's `presentationMeta` carries the structured alarms plus one display-ready markdown; over 30,000 serialized characters it returns `{}`, which every meta narrower rejects, so replayed UIs and transport cards fall back to the raw result content. The canonical value is already bounded by `maxAlarms` and `maxDetailChars`; the ceiling only trips on very large `maxAlarms` deployments. `presentationMeta` cannot legally return `undefined` — the runtime snapshots and validates it — so the degradation is an explicit shape, not an omission.
- **Transport cards read the meta, not provider code, and one variable carries every outcome statement.** The Feishu package is untouched: a `cardTemplates` entry with `bindTool: alarm_query` binds the meta's `markdown`, which itself states the empty outcome (`No alarms found.`), the shown-of-total count, and the cut notice — the same shared constants behind the model text — so no surface can show a bare list that reads as the complete result. The capability overlay carries the alarm trio alone over any profile; the separate Feishu composition example carries the complete bot plus the card entry, and the cardTemplates entry is the card's single home — the discipline the planned card-set seam will formalize for every skill-owned card.

## Alternatives considered

**A generic REST-query tool with per-tenant JSON paths.** One tool plus mapping config reads any system, but every field name becomes deployment data: mislabeled severities surface as wrong answers instead of load-time contract failures, and the model parses vendor shapes the type system never sees. The dedicated seam pays three packages once and every future system inherits the pattern.

**Retrying decode failures.** Retrying the whole request on a malformed body treats "the upstream answered wrongly" like "the upstream answered late"; it doubles load for a deterministic failure. The retry loop therefore wraps transport only, and decoding runs after it.

**Omitting the meta entirely over the ceiling.** The runtime validates `presentationMeta`'s return as lossless JSON, so an `undefined` return is a tool-output failure, not an omission. The empty-object degradation keeps the honest fallback (raw result content) without an error path.

## Consequences

Feishu renders alarm cards from configuration alone; the alarm trio is usable from the Web UI immediately (generic card over the meta markdown); and the wire contract is the integration surface a non-conforming alarm system must adapt to (adapter service or its own provider package). Tests cover the seam's selection ladder, resolution, caps, HMR-safe registration, and the shared ISO-8601 check; the provider against a local HTTP server (mapping, auth modes including the loud missing-token failure, retry, timeout, credential-resolution bounds, byte-budget boundary, path-prefix joins, strict decode); and the tool through a real Loader composition proving `maxAlarms` is live configurability, plus the detail cap, the outcome statements, and the meta ceiling. The repository-local `dev-fixtures/alarm-system` FastAPI process supplies the same strict response over a reusable real HTTP endpoint, with in-memory scenarios, separate read and administrative credentials, and bounded query faults; it deliberately omits persistence and proactive Feishu delivery. Its tests bind an ephemeral loopback port atomically, wait for readiness, and wait for Uvicorn shutdown. `dsh-system-prompt` gained one additive section-order constant (`TOOL_INTEGRATION_ALARM`), the only base-package change.

## Verification

- **The FastAPI fixture has an independent real-network check.** Its protocol suite verifies authentication, filtering, half-open time windows, strict management writes, scenario replacement, bounded faults, and a Uvicorn listener reached through an operating-system-assigned loopback port. The HTTP provider's package tests separately exercise the production transport implementation and failure rules.
- **The keyless Session fixture proves the assembled model-visible path.** [`snapshots/session/alarm-query`](../../../../snapshots/session/alarm-query/snapshot.yml) boots the shipped headless profile with the real seam, HTTP provider, and tool; only the model adapter is replayed. Its loopback fixture rejects the wrong method, filters, result limit, `Accept` header, or bearer token, while the Session pins the `alarm_query` call, truncated canonical result, presentation metadata, and final model turn. This scenario is deterministic CI evidence, not a simulation of Feishu.
- **Real Feishu delivery remains manual evidence.** On 2026-09-20, an owner-run local UAT used the capability overlay, the FastAPI fixture, a live model service, and the real Feishu transport; alarm results completed that path successfully. This run does not certify a target vendor's authentication, schema drift, throttling, or production availability, which require a separate provider-level acceptance run.
